# Wiki

نطاق مستقل (`wiki.hostaka.fun`) يخدّم Hostaka Wiki — نظام نشر منظّم
بالمواضيع (extensions): أي مستخدم يكتب منشور تحت موضوع (مثلاً
`chat-error`)، وأي مستخدم ثاني يقدر ينضم لنفس الموضوع بكتابة نفس
الاسم بالضبط. كل منشور (وكل رد عليه) ياخذ توكن ورابط مستقل خاص فيه،
بنفس نمط `orbithub`/`aethercast`/`console`/`apps` بالضبط.

## البنية

```
wiki/
├── server.js              ← السيرفر (static + بروكسي /api + حقن OG)
├── package.json
├── vercel.json
├── .env.example
└── public/
    ├── index.html / browse.js / browse.css   ← الرئيسية: بحث + تصفح المواضيع (/)
    ├── topic.html / topic.js / topic.css     ← صفحة موضوع (/:extension)
    ├── post.html / post.js / post.css        ← منشور فردي — أصلي أو رد (/:extension/:token)
    ├── new.html / new.js / new.css           ← نموذج منشور جديد (/new)
    ├── common.js                             ← إعدادات مشتركة (oauth/ثيم/لغة/api)
    ├── theme.css / shared.css / shared.js
    ├── emoji.css / emoji.js / emoji-catalog.json
    ├── i18n.js / modal.js / protect.js
    ├── translations/ar.json / en.json
    └── wiki-icon.png                         ← أيقونة placeholder
```

كل منطق المصادقة وقاعدة البيانات يبقى بالكامل على السيرفر الرئيسي
(`hostaka.fun`). هذا السيرفر بس واجهة + بروكسي شفاف لـ `/api/*` تجاهه،
تماماً بنفس فكرة `apps` (راجع `apps/README.md` لو تبي تفاصيل آلية
البروكسي والـ OAuth الصامت، هي نفسها هنا حرفياً).

## كيف يشتغل نظام المواضيع (extensions)

- **منشور أصلي** (parent فاضي) يحدّد الموضوع اللي يظهر تحته — أول
  واحد يكتب موضوع جديد "ينشئه" ضمنياً، وأي منشور ثاني بنفس اسم
  الموضوع (بعد تطبيع بسيط: حذف المسافات الزايدة، توحيد لحالة أحرف
  صغيرة) ينضم لنفس الصفحة.
- **الرد/التعليق** يُخزَّن بنفس الجدول تماماً (`parent_id` يشاور
  للمنشور اللي تم الرد عليه)، وياخذ توكن ورابط مستقل مثل أي منشور —
  يعني تقدر ترد على رد (thread متداخل)، وكل مستوى له رابط تقدر
  تشاركه لحاله.
- كل منشور/رد يُعرض تلقائياً باسم الناشر وتاريخ النشر، وشارة **admin**
  جانب الاسم لو حساب الناشر أدمن.
- **النشر فوري** — ما فيه حالة "قيد المراجعة"، المنشور يظهر للكل
  فور إرساله.
- **صاحب المنشور يقدر يعدّل أو يحذف** منشوره/رده في أي وقت (حذف
  المنشور الأصلي يحذف كل الردود عليه تلقائياً بقاعدة البيانات —
  `ON DELETE CASCADE`).

## نقاط الـ API (كلها بـ hostaka-main)

| المسار | الوصف |
|---|---|
| `GET /api/wiki/extensions?q=` | بحث/تصفح المواضيع (عدد المنشورات + آخر نشاط) |
| `GET /api/wiki/extensions/:extension/posts` | كل المنشورات الأصلية تحت موضوع |
| `GET /api/wiki/posts/:token` | منشور واحد (أصلي أو رد) |
| `GET /api/wiki/posts/:token/comments` | الردود المباشرة على منشور |
| `POST /api/wiki/posts` | نشر منشور أصلي جديد — تسجيل دخول مطلوب |
| `POST /api/wiki/posts/:token/comments` | إضافة رد — تسجيل دخول مطلوب |
| `PUT /api/wiki/posts/:token` | تعديل منشورك/ردك (المالك فقط، أو مشرف/أدمن) |
| `DELETE /api/wiki/posts/:token` | حذف منشورك/ردك (المالك فقط، أو مشرف/أدمن) |
| `GET /api/admin/wiki-posts?q=` | كل المنشورات للمراجعة (لوحة console) |
| `DELETE /api/admin/wiki-posts/:id` | حذف نهائي (أدمن فقط) |

الصور (لقطة شاشة اختيارية بالمنشور/الرد) تُرفع عبر `/api/upload`
الموجود أصلاً بالسيرفر الرئيسي — نفس آلية `apps` بالضبط.

## حقن Open Graph

لما حد يشارك رابط `/:extension/:token`، `server.js` يجيب بيانات
المنشور من `GET /api/wiki/posts/:token` على السيرفر الرئيسي قبل ما
يرسل الصفحة، ويحقن العنوان (أو "رد من @username" لو كان رد بلا
عنوان) والوصف والصورة (لو موجودة) كوسوم `<meta>` — نفس فكرة `apps`
لصفحة التطبيق الفردي.

## اختبار محلي

```bash
npm install
cp .env.example .env   # اختياري، القيمة الافتراضية تكفي
npm start
# افتح http://localhost:3000
```

## النشر على Vercel

1. مشروع Vercel جديد من هذا المستودع.
2. Vercel بيكتشف `vercel.json` تلقائياً.
3. من Settings → Domains: أضف `wiki.hostaka.fun`.
4. من DNS حق `hostaka.fun`: أضف سجل `CNAME` باسم `wiki` يشاور على
   القيمة اللي يعطيك ياها Vercel.

## متغيرات البيئة على Vercel

| المتغير | مطلوب؟ | القيمة |
|---|---|---|
| `HOSTAKA_API_BASE` | ❌ اختياري | `https://hostaka.fun` (افتراضية بالكود أصلاً) |

ما فيه قاعدة بيانات ولا JWT secret هنا — كلها على المشروع الرئيسي فقط.

## تسجيل الدخول بين النطاقين

نفس آلية `apps` بالضبط: سحب صامت من `oauth.hostaka.fun/api/token`
أولاً، وفي حال فشل، تمرير احتياطي للتوكن عبر رابط `?token=` من
تحويلات `hostaka.fun` (`/wiki`, `/wiki/new`, `/wiki/:extension`,
`/wiki/:extension/:token`). لا حاجة لأي تعديل على `oauth` — نفس
الـ CORS العام يغطي `wiki.hostaka.fun` تلقائياً.

## لوحة المراجعة (console)

مراجعة/حذف المنشورات المسيئة تصير من `console.hostaka.fun` — تبويب
"Wiki" جديد بالسايدبار (بحث + حذف، بدون موافقة/رفض لأن النشر فوري)،
مو من هذا المستودع.

## الشعار

لا يوجد شعار مخصص بعد — `wiki-icon.png` أيقونة placeholder مولّدة
بتدرّج أزرق يميّزها بصرياً عن باقي الخدمات (بدل التدرّج الذهبي
لـ`--avatar-gradient` المستخدم بباقي المنصة)، عشان تكون واضحة كخدمة
منفصلة. تستبدل لاحقاً بشعار حقيقي.
